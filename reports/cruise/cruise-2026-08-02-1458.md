## 4. 🔴 新发现：redeploy workflow 与 ark-pro 目录耦合（待决策信息补充）

排查「为何 ark-pro 目录持续存在」时发现根因：

```
.github/workflows/redeploy-cf-pages.yml
  → 每次触发向 ark-pro/deploy-marker.txt 追加时间戳并 push
  → git log 中的 "chore: trigger CF Pages redeploy" 系列 commit 均由此产生
```

### 对既有决策的影响

上轮遗留决策「如何处置 ark-pro/functions/」（两套同名 track.js 契约互不兼容）出现新约束：

- **若选方案 1（删除 ark-pro/）**：必须同步修改 workflow，把 deploy-marker 移到别处（如根目录 `deploy-marker.txt`），否则 CI 会因 `git add ark-pro/...` 失败而报错
- **若选方案 2（保留+废弃标记）**：workflow 继续写入即可，但标记要覆盖到 deploy-marker.txt

**修正建议：方案 1 依然是更优解**——删除 ark-pro 时把 workflow 的 marker 路径同步改到根目录，一石二鸟：既拆陷阱，又保留 redeploy 触发机制。
