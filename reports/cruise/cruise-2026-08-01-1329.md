## 3. 缺陷二：Discussions 公开评论 JSON 未解包（🟡 需主人授权）

### 发现
Discussion #7【免费诊断日】下，2026-07-31 06:46:02 发布的评论
（comment_id `17850180`）**正文是一整段未解包的 JSON 字符串**：

```
{"body":"【找人启事 · 带温度】\n\n今天中午 12:10 左右，有一位朋友在 ARK 诊断页尝试付款…"}
```

读者看到的是 `{"body":"…\n\n…"}` 这样的原始转义文本，而非正常段落。

### 为什么这条最伤
这条恰恰是**信任建设内容**——内容本身在说「ARK 背后不是机器人，是一个真人」
「你愿意掏钱，我愿意亲手把诊断书送到你手上」，是找回一位付款失败用户的致歉启事。

**一条声明「我不是机器人」的留言，以机器人 JSON 报错的形态呈现在公开讨论区。**
这是全站信任叙事上最刺眼的一处自相矛盾，且已公开挂了 31 小时。

### 排查范围
已全量扫描 Discussions #2–#7 全部评论 + Issue #1 全部评论，
**同型问题仅此 1 例**，非系统性批量污染。

### 修复受阻
已恢复出干净正文（存于 `/tmp/ark_fixed_comment.md`，内容完整无损），
但两条改写路径均被 token 权限拦截：

| 尝试 | 结果 |
|---|---|
| GraphQL `updateDiscussionComment` | `FORBIDDEN: Resource not accessible by personal access token` |
| REST `PATCH .../discussions/7/comments/17850180` | `404 Not Found`（Discussions 无此 REST 端点） |

当前 PAT 对仓库是 ADMIN（`viewerCanUpdate: true`），但**缺 Discussions:write 细粒度权限**。

   为该 token 勾选 **Discussions: Read and write**，我下轮巡航自动修复；
2. **主人手动改**：直接编辑该评论，把外层 `{"body":"…"}` 去掉、

## 5. 本轮方法论沉淀

07-31 与 08-01 两轮巡航连续命中同一族缺陷，可固化为巡航常规检查项：

> **「可达性检查」应与「可用性检查」并列。**
> 每新增一个页面，除验证 HTTP 200 外，必须验证：
> 全站至少存在 N 条入链，且其中至少 1 条位于漏斗上游（首页/README）。
> 200 只证明文件在，不证明用户走得到。

建议后续把该检查脚本化（遍历 docs/*.html，构建入链图，
对入链数 < 2 的非首页页面告警），纳入巡航自动化。
